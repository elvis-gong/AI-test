# Ascend C 性能优化记录

## 优化目标

题面要求全部 15 个 case 精度通过才计分。单 case 得分为 `100 / (1 + log_1.5(t / T_baseline))`，最终取 15 个得分的算术平均。应对比各 case 的得分变化，不能只看某个大 case 加速比或平均延迟；同分时按提交时间排名。

本轮仅修改 kernel.asc 和说明文档。run.sh、main.asc、scripts/、CMakeLists.txt 和 data_utils.h 保持 HEAD 状态，继续通过原平台计时/验证入口验收。

## 已实现的变化

| 路径 | 原实现 | 优化实现 |
| --- | --- | --- |
| k=1 | 标量扫描 UB | ReduceMax，不执行排序 |
| k>1 | O(E*k) 标量插入 | Sort32 生成 32 元素有序段，再用 MrgSort 四路归并；必要时最后二路归并 |
| 行调度 | 多核交错写入短输出行 | 均衡分配连续行，预期减少缓存竞争并改善顺序访存；效果待实测 |
| 非 2 的幂 E | 字节搬运和转换 | 保留字节搬运；排序补至下一个 2 的幂，所有无效 lane 使用最小有限 FP32 值 |
| 提取 | 标量插入和清零 | 仅提取前 k 个值；其余评分 lane 用一次 Duplicate 初始化 |
| 选中 logits 全部在 [-2,20] | 无条件计算八项多项式及选择 | 只执行 Exp、Adds、Ln、Sqrt |
| 选中 logits 全部 >20 | 无条件 Exp/Ln 等 | 仅执行 Sqrt |
| 选中 logits 全部 <-2 | Ln 与多项式同时执行 | 跳过 Ln，使用原八项稳定级数 |
| FP32 输出 | 复制到第二个 UB 缓冲区 | 直接使用 VECOUT 评分缓冲区 |
| 输出同步 | MTE3->V 和 MTE3->S | 保留 MTE3->S；下一行经 S->MTE2->V 串联，保护缓冲区复用 |

选择的 device 工作由逐值标量读写转为排序/归并指令。所有评分均为 FP32，未改变精度要求、输出 dtype 或降序语义。对于有限值，补齐值不会大于真实输入；等于最小有限值时输出分数仍相同。NaN/Inf 输入域仍以正式规则为准。

每核 UB 分配上界：FP32 排序路径 30,464 字节，FP16 排序路径 28,416 字节；k=1 不分配排序和索引缓冲区，分别为 10,240 / 8,192 字节。缓冲区大小均为 256 字节的整数倍，维持 Sort32 需要的源/目标对齐。实际工具链的 allocator 元数据及平台 UB 容量仍需编译/设备核验。

### 当前候选的实现

- 每核少于 4 行时保留已通过的单行 Kernel，避免批处理初始化拖慢小规模输入。
- 否则使用 BatchKernel，按 E、k、每核行数和 120 KiB 张量预算选择 4/8/16 行 tile。
- 多行共享一次输入 DMA、Sort32、各级 MrgSort、Gather、评分和输出 DMA。归并末级两路列表分成四个有序半段，满足重复四路归并条件，保持每行独立排序。
- Gather 通过字节偏移表直接取各行前 k 个值，热循环取消逐行 k 次 Scalar 取值。只在初始化生成一行偏移，其他行用 int32 Vector Adds 扩展。
- k=1/E=64 用一次 WholeReduceMax 处理整个 tile；其他 k=1 保留各行 ReduceMax，但搬运、评分、输出合批。
- FP32 的输入 UB 直接用于排序，无输入到第二个 FP32 缓冲区的 Adds 复制；FP16 整个 tile 统一转为 FP32。
- 评分行 stride 按 16 元素补齐，k=6 时每行计算 16 个 lane，减少旧路径固定 64 个 lane 的无效计算。尾 tile 无效行仅参与内部计算，不读写额外 GM 行。
- 输出 UB 采用按行对齐 stride；DataCopyPad 的 blockLen 为实际 k 字节数，UB stride 按 32 字节块计、GM stride 为零，保持 (T,k) 紧凑输出。
- 仍使用原稳定数学公式和八项负数级数，不降低中间精度。单行与批处理共用 ScoreValues，避免两套数值逻辑分叉。

规划每核张量空间不超过 120 KiB，留出对齐及平台开销余量。该预算不表示已查询实际设备 UB。CPU 模型已验证的分配峰值为 120,832 字节。相比约 30 KiB 单行排序路径，额外空间用于多行数据和排序中间结果，不产生 GM workspace。

## 第三轮：精确截断归并与统一内核（2026-10-15）

本节对应当前 kernel.asc，前两轮描述保留为历史记录。尚无本轮设备耗时，不能据此宣称评分提升。

### 核心算法替换

k>1 不再完整归并每行 E 个元素。Sort32 得到有序小段后，每段只保留 q=向上对齐(k,8) 个候选（初始段最多 32 个）；每个非末级归并也截断至 q，最后一级直接提取前 k 个值。某个被丢弃的值前面已有至少 k 个不小于它的本段元素，因此丢弃它不会改变最终 top-k 的值。相等值对应的 ID 不输出，候选截断无需额外维护稳定索引。

下面统计 E=1024 时每行各级归并输入的元素数量，不包含共同的 Sort32 扫描、额外的 Copy 和同步开销；比值不是实际加速比。

| k | 完整归并三层 | 截断归并三层 | 归并元素总数比 |
| --- | --- | --- | --- |
| 6 | 1024 / 1024 / 1024 | 256 / 64 / 16 | 3072 / 336 ≈ 9.14 |
| 16 | 1024 / 1024 / 1024 | 512 / 128 / 32 | 3072 / 672 ≈ 4.57 |
| 32 | 1024 / 1024 / 1024 | 1024 / 256 / 64 | 3072 / 1344 ≈ 2.29 |
| 64 | 1024 / 1024 / 1024 | 1024 / 512 / 128 | 3072 / 1664 ≈ 1.85 |

候选以 value/index 成对存储，使用带 stride 的向量 Copy 压紧前缀。归并段长度保持硬件对齐；最后两个有序段拆成四个有序半段，使 MrgSort 的 repeatTimes 能同时处理多行。次级 ping-pong 缓冲区只按候选容量分配，并保留 Gather 所需的访问容量。

k=1 完全跳过排序：E 补齐到 64 时仅一次 WholeReduceMax；其余形状先对所有 64 元素块归约，再通过稀疏 mask 对各行的块最大值归约。两步都跨行重复执行，消除逐行 ReduceMax 调用。

### 逻辑精简

- 合并单行与 BatchKernel 为一个 Kernel<T, MaxOnly>，k=1 的排序分支由编译期特化消除；统一支持 1/2/4/8/16 行 tile。
- DMA 描述、向量 Copy stride、归并计划和 Gather 偏移在 Init 中准备，热循环只更新有效行数。
- 输入缓冲区及 padding 只初始化一次；计算不修改输入。尾 tile 的未使用内部行保留已定义的数据，与有效行独立处理，只读写实际 GM 行。
- 评分保留 FP32 及八项负数级数，合并一般数值分支；保留常见区间与全大于 20 的快速路径，以及必要的越界/协议检查。
- 当前 kernel.asc 为 430 行；每核张量分配仍限制为 120 KiB，不申请 GM workspace。

### 本轮已执行验证

从实际 kernel.asc 提取统一 Kernel 类，在同步 CPU API 模型下以 C++14、-O2、-Wall、-Wextra、-Werror 编译，并执行 **5622 组配置**。覆盖 FP16/FP32、全部 E=64..1024 的 k=1/6、多组 k 至 64、跨核划分、单行和批处理、尾 tile、重复值、赢家集中在末段、负数、-2/20 阈值、全大值与输出 guard。

最终评分与独立的完整排序/数学 oracle 比较；每组额外检查最后 tile 所选 logits 与完整排序前 k 项逐值一致。模型按字节检查 tensor 边界及 DMA stride，测得每核张量分配峰值 **120,832 字节**。这些检查不验证真实向量指令误差、CANN 接口兼容性或异步流水。
