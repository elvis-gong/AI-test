# Ascend C 性能优化记录

## 优化目标

题面要求全部 15 个 case 精度通过才计分。单 case 得分为 `100 / (1 + log_1.5(t / T_baseline))`，最终取 15 个得分的算术平均。应对比各 case 的得分变化，不能只看某个大 case 加速比或平均延迟；同分时按提交时间排名。

本轮仅修改 kernel.asc 和说明文档。run.sh、main.asc、scripts/、CMakeLists.txt 和 data_utils.h 保持 HEAD 状态，继续通过原平台计时/验证入口验收。

## 已实现的变化

| 路径 | 原实现 | 优化实现 |
| --- | --- | --- |
| k=1 | 标量扫描 UB | ReduceMax，不执行排序 |
| k>1 | O(E*k) 标量插入 | Sort32 生成 32 元素有序段，再用 MrgSort 四路归并；必要时最后二路归并 |
| 行调度 | 多核交错写入短输出行 | 均衡分配连续行，预期减少缓存竞争并改善顺序访存；效果待实测 |
| 非 2 的幂 E | 字节搬运和转换 | 保留字节搬运；排序补至下一个 2 的幂，所有无效 lane 使用最小有限 FP32 值 |
| 提取 | 标量插入和清零 | 仅提取前 k 个值；其余评分 lane 用一次 Duplicate 初始化 |
| 选中 logits 全部在 [-2,20] | 无条件计算八项多项式及选择 | 只执行 Exp、Adds、Ln、Sqrt |
| 选中 logits 全部 >20 | 无条件 Exp/Ln 等 | 仅执行 Sqrt |
| 选中 logits 全部 <-2 | Ln 与多项式同时执行 | 跳过 Ln，使用原八项稳定级数 |
| FP32 输出 | 复制到第二个 UB 缓冲区 | 直接使用 VECOUT 评分缓冲区 |
| 输出同步 | MTE3->V 和 MTE3->S | 保留 MTE3->S；下一行经 S->MTE2->V 串联，保护缓冲区复用 |

选择的 device 工作由逐值标量读写转为排序/归并指令。所有评分均为 FP32，未改变精度要求、输出 dtype 或降序语义。对于有限值，补齐值不会大于真实输入；等于最小有限值时输出分数仍相同。NaN/Inf 输入域仍以正式规则为准。

每核 UB 分配上界：FP32 排序路径 30,464 字节，FP16 排序路径 28,416 字节；k=1 不分配排序和索引缓冲区，分别为 10,240 / 8,192 字节。缓冲区大小均为 256 字节的整数倍，维持 Sort32 需要的源/目标对齐。实际工具链的 allocator 元数据及平台 UB 容量仍需编译/设备核验。

## 本地验证

在 build/optimization_checks/ 下建立同步 CPU API 模型，执行从实际 kernel.asc 提取的 Kernel 类；没有修改 scripts，也没有将模型作为 NPU 实现提交。

- C++14 开启 `-Wall -Wextra -Werror` 编译通过。
- 共 2090 组配置通过：两种 dtype；所有 E=64..1024 的 k=6；重点 E 的 k=1/4/6/16/32/64。
- 对照完整评分降序排序的独立数学 oracle；覆盖随机、重复值、大正负数、-2/20 阈值附近。
- 检查 UB/GM 访问范围、输出 guard、行分配以及降序输出。
- CPU 模型使用同步操作，不验证真实 NPU 指令误差、流水事件时序、硬件 DMA 或耗时。

## 设备验收与评分对照

- [ ] 使用原模板编译优化 kernel，确认 Sort32/MrgSort/ReduceMax API 兼容。
- [ ] 15 个 case 全精度通过，再采集优化耗时。
- [ ] 使用相同硬件、版本、case、预热/重复及计时口径对比旧版。
- [ ] 按题面公式分别计算每个 case 的新旧得分，再比较均值。
- [ ] 若小 case 排序启动开销较高，根据实测考虑局部选择；若大 T 受逐行搬运限制，评估多行批处理。

暂无优化版 NPU 耗时和分数，不填写预估加速比作为实测结果。
