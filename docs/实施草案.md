# SqrtSoftplusTopK 题目解读与实施草案

## 1. 题目在做什么

MoE 路由中，每一行代表一个 token，每一列代表一个专家。输入是 logits，不是概率。先将每个 logits 变为 `sqrt(ln(1+exp(x)))`，再按每行分数降序取前 k 个。输出仅为分数，无 ID、无归一化、无专家分组、无附加偏置。

例如原题的 `[1,2,3,4]` 与 `[4,3,2,1]`，k=2 时都得到约 `[2.004532,1.746020]`。该 E=4 示例用于解释语义，正式输入 E 最小为 64。

| 项目 | 要求 |
| --- | --- |
| 输入 | ND，(T,E)，float16 或 float32 |
| T | 1 到 131072 |
| E | [64,1024]，允许非 2 的幂 |
| k | 默认 6；1 到 64，且不超过 E |
| 输出 | (T,k)，同输入类型，降序 |
| 中间精度 | softplus 与 sqrt 必须使用 FP32 |
| 数值稳定性 | x>20 时 softplus=x；大负数结果趋近 0 |
| 评分门槛 | 全部 15 个 case 精度通过后才评分 |

参考代码没有最后转回输入类型，但输出契约要求同输入类型。本项目参考实现补上最终 cast。题目精度段落提及 bfloat16/int32，而算子接口仅支持 float16/float32，因此不推断额外类型支持。

题面分别给出绝对/相对误差阈值：FP32 为 1e-4，FP16 为 1e-3；两者如何组合、相对误差零值分母如何处理、是否采用严格小于，需以正式评测脚本为准。

性能公式 `100 / (1 + log_1.5(t / T_baseline))` 中 T 表示基线耗时，与 token 数符号重名。15 个 case 分数取均值，同分按提交时间排名。公式在某些比值下可能出现异常分母，不自行补充截断规则，以平台实现为准。

## 2. 关键优化候选：先选择，再评分

对于有限实数，softplus 导数为 sigmoid(x)>0，sqrt 在非负区间单调递增。因此数学上排序 logits 与排序 score 得到相同的值序列：

`topk(score(x)) = score(topk(x))`。

由此可以只对 k 个选中 logits 计算 exp/log/sqrt，而非每行 E 个。仍然必须读入和比较 E 个输入，所以不能把 E/k 直接当成整体加速比。FP32 舍入、下溢及 ties 需要实际验证；仅输出值使 tie ID 顺序无需处理。NaN/Inf 的输入域及排序语义未在题目中指定，正式规则明确前不能擅自保证该域的等价性。

## 3. 实施阶段

### 阶段 A：开发基线（本次初始化）

- 建立严格 shape/dtype 契约，完整评分 PyTorch oracle 及先选后评分候选。
- 提供不依赖 torch 的 CLI smoke 和契约检查。
- 留出 host、device 和 benchmark 目录，不编造设备 API。

### 阶段 B：可提交正确性基线

取得官方工程模板，确认 NPU 型号、CANN/Ascend C 版本、编译器、Python/torch_npu 配套、调用签名及提交格式。使用对应官方文档确认排序、搬运和 FP32 数学指令。

首版按行分配工作：输入搬入 UB，FP16 转 FP32，执行稳定评分，降序排序并取 k，转回目标 dtype 后写出。优先正确性和可编译性，不在未验证前依赖特定排序接口。

Host 负责输出推导、输入校验、核数及每核行数调度。T 小时需评估核利用率；T 大时每核循环处理多行。末核和末行必须有边界处理。

### 阶段 C：融合优化

验证先选后评分；比较全排序与局部 top-k。当 k=1 时评估行最大值路径；小 k 评估选择/局部归并；k 较大时评估排序路径。选择算法必须依据目标硬件 API 和实测决定。

按 E/k/dtype 划分 tiling 候选，评估多行批处理和流水。UB 预算计入输入、FP32 转换、排序临时区、输出、对齐及缓冲，不能只按输入字节估算。输出 k 并非总满足 DMA 对齐，必须设计安全的尾部写出，不得越界覆盖邻行。

### 阶段 D：精度与性能验收

先跑完整正式精度集合，再测正式 15 case；记录版本、预热、重复、同步及 kernel/端到端口径。以真实评分均值选择方案，保留可回退的正确基线。

## 4. 自建验证矩阵

- 两种 dtype、全部 E，并重点覆盖 65/96/127/255/1023 等非 2 的幂，T 覆盖 1/2、核数附近、非整除行数、512 及大规模 131072（大规模按设备资源分批运行）。
- k 覆盖 1/6/64；所有输出检查 shape、dtype、降序及与 oracle 的误差。
- 分布覆盖随机、全相等、重复极大值、递增/递减、大正数、大负数、零和 20 两侧。
- 除候选对 oracle，还要将最终 NPU 结果对 oracle，并核验正式评测器误差判定。
- 当前单元测试是小规模本地筛查，不是完整矩阵或正式评测替代品。

默认运行保持 bash run.sh，仅验证模板 case0。没有 CANN 工具链时不能确认真实编译与设备精度；后续设备覆盖与性能任务详见开发清单。

## 第二轮：以 UB 换取批处理效率（2026-10-15）

用户提供上一版全部 15 case Pass 的耗时，较大 case 与最优值相差约 10–36 倍。本轮保留每核少于 4 行的单行路径，为其他输入增加自适应 4–16 行 BatchKernel。多行共享 DMA、排序归并、Gather 和评分调用，FP32 输入直接复用，规划的每核张量空间限制 120 KiB。仍使用原 run_kernel 入口和原测试文件，具体 case 参数未知时按输入描述自动分派，不根据 case 编号硬编码。

原八项稳定 softplus 多项式不降低阶数；数值逻辑提为两条路径共用的 ScoreValues。上一版全 Pass 不代表批处理版通过，必须重新全量验证。

## 第三轮：截断归并 top-k（2026-10-15）

当前两套路径合并为 Kernel<T, MaxOnly>，统一规划 1–16 行 tile。k=1 通过模板布尔特化选择分级 WholeReduceMax，其他 k 在 Sort32 后及中间归并后截断每段前 q 个候选（q 为 k 对齐至 8 的值）。丢弃的项在自身有序段内已有至少 k 个不小于它的值，不能改善全局 top-k；输出值精确，非采样或近似选择。

所有 DMA/归并/截断几何在初始化准备，输入计算只读，所以 padding 仅初始化一次。尾 tile 多余内部行沿用已初始化数据，不读写额外 GM 行，也不与有效行归并。保留 FP32 评分和原八项稳定级数。当前候选仍需设备全精度和耗时复测，详见性能优化记录。
